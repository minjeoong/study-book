qa:
  - q: "SFT와 CPT의 차이는?"
    a: "SFT는 모범 답안이 있는 (질문, 정답) 쌍으로 모델이 원하는 형식과 태도로 답하도록 가르치는 지도학습이다. CPT는 라벨 없는 도메인 원문을 대량으로 계속 읽혀 지식 자체를 두껍게 새기는 단계다. 실습에서 679건으로 한 SFT는 지식 주입보다 '결론 → 적용 규정 → 확인 안내' 답변 습관을 고정하는 효과가 컸고, 고유 코드 같은 사실은 일부만 학습됐다."
  - q: "RLHF와 DPO의 차이는?"
    a: "둘 다 여러 답변 중 더 나은 쪽을 고르도록 사람의 선호를 반영하는 정렬 단계다. RLHF는 선호 데이터로 보상 모델(채점 로봇)을 따로 학습한 뒤 PPO 같은 강화학습으로 정책을 업데이트한다. DPO는 보상 모델 없이 (prompt, chosen, rejected) 비교 쌍을 직접 학습하는 더 단순한 방식이다."
  - q: "학습 데이터가 부족하면 어떻게 하나?"
    a: "지식 증류를 SFT의 앞 단계로 붙인다. 소량의 실제 사례를 시드로 더 큰 교사 모델에게 주고 비슷한 형식의 질문·답변을 대량 생성시킨 뒤, 사실 오류·형식 불일치를 걸러 실제 데이터와 합쳐 SFT·LoRA로 학습한다. 단, 교사도 모르는 사내 고유 규정은 증류로 주입할 수 없고, 상용 API를 교사로 쓰면 약관상 경쟁 모델 학습 제한을 확인해야 한다."

| 단계 | 데이터 | 가이드 비유 | 바뀌는 것 |
|---|---|---|---|
| CPT (지속 사전학습) | 라벨 없는 도메인 원문 대량 | 도메인 책을 계속 읽힘 | 지식 자체 |
| SFT / Instruction Tuning | (지시·질문, 모범 답변) 쌍 | 모범답안집으로 글쓰기 과외 | 답변 형식·태도·지시 이행 |
| RLHF | 답변 순위 + 보상 모델 + PPO | 채점 로봇의 실시간 코칭 | 사람 선호에 맞는 답 |
| DPO | (prompt, chosen, rejected) 비교 쌍 | 기출문제집으로 직접 학습 | 사람 선호에 맞는 답 (더 단순) |

```flow
데이터 부족 확인 :: 사내 라벨 데이터가 수백 건 수준
시드 예시 제공 :: 실제 사례 일부를 교사 모델에 전달
합성 데이터 생성 :: 교사가 유사 형식의 질문·답변을 대량 생성
품질 검수 :: 사실 오류·형식 불일치·유해 표현 필터링
SFT · LoRA 학습 :: 실제 데이터 + 합성 데이터로 학생 sLLM 학습
```

> [!tip] 왜 지금 SFT가 필요한가 (가이드1)
> Base LLM은 우리 회사 규정을 원래 모르고(지식의 간극), 알아도 회사가 원하는 형식으로 말하지 못함(말하는 방식의 간극). 그렇다고 사전학습부터 다시 하는 건 막대한 비용 — "이미 잘 자란 사전학습 모델 + 가벼운 파인튜닝"이 실무의 기본 조합.
