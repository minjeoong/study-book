qa:
  - q: "HNSW 알고리즘을 설명하면?"
    a: "Hierarchical Navigable Small World로, 벡터들을 여러 층의 그래프로 연결해 둔다. 맨 위층은 소수의 노드만 장거리로 이어져 있어 고속도로처럼 목적지 근처까지 크게 이동하고, 아래층으로 내려갈수록 노드가 촘촘해져 주변을 세밀하게 탐색한다. 100만 건이 있어도 실제 거리 계산은 수십~수백 건이라 1~5ms에 끝나고, 새 데이터는 가까운 이웃 몇 개와 링크만 이으면 돼 실시간 추가에도 강하다."
  - q: "ANN은 정확도를 포기하는 건데 괜찮은가?"
    a: "사용자는 10초 걸리는 100% 정답보다 0.01초 만에 나오는 99.9% 정답을 원한다. RAG에서는 어차피 상위 몇 개 후보를 뽑아 LLM이나 Reranker가 다시 판단하므로, 근사로 인한 아주 작은 누락보다 속도 이득이 훨씬 크다. 정확도가 더 필요하면 그래프 연결 수나 탐색 범위 파라미터를 키워 속도와 recall을 맞바꾼다."

```flow
1단계 최상위 계층 :: 서울·대전·대구·부산만 연결된 고속도로, 크게 점프해 목적지 근처로
2단계 중간 계층 :: 한 층 내려와 시·구 단위 도로로 방향을 좁힘
3단계 최하위 계층 :: 촘촘한 골목길(밀집 벡터), 주변 몇십 개만 비교해 최종 확정
```

```compare
전수 조사 (Brute-force) | ANN (HNSW)
비교 대상 | 저장된 모든 벡터 (100만 건이면 100만 번) | 그래프를 따라 수십~수백 건
정확도 | 100% 최근접 | 근사 (99.9% 수준)
속도 | 데이터가 늘면 수 초 이상, 동시 접속 시 서버 과부하 | 1~5ms
데이터 추가 | 다시 다 비교 | 가까운 이웃과 링크만 연결
```

> [!tip] 면접 보강: HNSW 튜닝 파라미터
> Qdrant 기준 `m`(노드당 연결 수)과 `ef_construct`(인덱스 구축 시 탐색 폭)를 키우면 정확도↑·메모리와 구축 시간↑, 검색 시 `hnsw_ef`를 키우면 recall↑·지연↑. Flat·IVF·PQ와의 비교는 RAG Pipeline 과목 노트 참고.
