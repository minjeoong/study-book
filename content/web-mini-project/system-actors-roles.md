  - 기업 계정은 관리자 승인 후에만 사용 — 허위 · 오등록 사고를 막는 신뢰 장치

qa:
  - q: 왜 관리자 승인 단계를 두었나요?
    a: '유출 사고 정보는 사용자를 불안하게 만들 수 있고 피해 대상 해시까지 다루기 때문에, 아무 기업이나 등록할 수 있으면 허위·오등록 위험이 큽니다. 그래서 기업 가입과 사고 공개 모두 플랫폼 관리자의 승인을 거치게 했습니다. 기업 계정은 가입 직후 승인 대기(PENDING)이고, 승인된 계정만 로그인과 사고 등록이 가능합니다.'
  - q: 액터를 먼저 정의하면 어떤 점이 좋나요?
    a: '누가 어떤 데이터를 만들고 볼 수 있는지가 먼저 정해져서 화면, 테이블, API 권한이 일관되게 나뉩니다. 이 프로젝트에서도 액터 셋이 그대로 계정 테이블 셋(company_account, admin, member)과 API 태그(Company, Admin, Member)로 이어졌습니다.'

```flow
기업 담당자 :: 사고 등록 + 피해 대상 이메일 해시 제출
플랫폼 관리자 :: 심사 — 승인하면 공개, 반려하면 사유 기록
일반 사용자 :: 해시 일치 알림 → 내 유출 여부 확인 → 비밀번호 변경 체크
기업 담당자 :: 확인 통계 보기 · 보상 지급 상태 관리
```

| 액터 | 한 줄 역할 | 주요 기능 |
| --- | --- | --- |
| 기업 담당자 | 유출 사고를 등록하고 공지하는 외부 사용자 | 사고 등록(기본정보 → 유출 항목 → 영향 범위 → 보상정책 → 피해 대상 식별값 해시), 등록 사고 조회 · 반려 시 재제출, 사고별 반응 통계 · 보상 지급 현황 관리 |
| 플랫폼 관리자 | 신고의 신뢰도를 검증하는 운영자 | 기업 가입 승인, 사고 심사(승인 / 반려 + 사유), 전사 통계 대시보드, 사용자 문의 응대 |
| 일반 사용자 | 내 정보 유출 여부를 확인하고 대응하는 이용자 | 홈에서 내 유출 현황, 전체 사고 탐색 · 검색, 사고별 내 유출 대상 여부 확인(이메일 해시 대조), 비밀번호 변경 체크리스트 |

> [!note] 액터 → 설계 산출물
> 액터 3개가 계정 테이블 3개(company_account · admin · member), API 경로 3갈래(/companies/me · /admin · /members/me), 로그인 화면의 역할 탭 3개로 그대로 이어진다.
