keypoints:
  - 401은 누구인지 모름(인증 실패), 403은 누군지 알지만 권한 없음(승인 대기 기업)
  - 409는 요청 형식은 맞지만 현재 상태와 충돌 — 중복 가입, 반려 아닌 사고 수정
  - 남의 사고 조회는 403 대신 404 — 존재 여부조차 알려 주지 않는다
qa:
  - q: 401과 403의 차이는?
    a: '401 Unauthorized는 인증 실패, 즉 이메일·비밀번호가 틀려 누구인지 확인하지 못한 경우입니다. 403 Forbidden은 누구인지는 알지만 그 행동을 할 권한이 없는 경우로, 이 프로젝트에서는 관리자 승인을 기다리는 기업 계정의 로그인을 403으로 막고 승인 대기 중이라고 안내했습니다.'
  - q: 권한 없는 자원 조회에 403이 아니라 404를 쓴 이유는?
    a: '다른 회사의 사고 ID로 조회했을 때 403을 주면 "그 ID의 사고가 존재한다"는 정보가 새어 나갑니다. 존재하지 않는 경우와 권한이 없는 경우를 모두 404로 똑같이 응답하면, ID를 바꿔 가며 찔러 보는 방식으로도 다른 사용자의 정보를 알아낼 수 없습니다.'
  - q: 로그인 실패 메시지를 공통으로 쓴 이유는?
    a: '"없는 이메일입니다"와 "비밀번호가 틀렸습니다"를 구분해 알려 주면 어떤 이메일이 가입돼 있는지 알아내는 데 악용될 수 있습니다. 그래서 사용자·기업·관리자 로그인 모두 이메일/비밀번호 불일치를 같은 401 메시지로 처리했습니다.'

| 시나리오 | 코드 | 사용자 안내 · 시스템 동작 |
| --- | --- | --- |
| 승인 대기(PENDING) 기업 계정으로 로그인 | 403 | 관리자 승인이 끝나지 않은 계정임을 안내하고 로그인 차단 |
| 이메일 / 비밀번호 불일치 | 401 | 사용자 · 기업 · 관리자 로그인에 공통 인증 오류 메시지 |
| 이미 등록된 이메일 또는 사업자등록번호 | 409 | 중복 가입을 막고 기존 계정으로 로그인 안내 |
| REJECTED가 아닌 사고 수정 시도 | 409 | 반려된 사고만 수정 · 재제출할 수 있게 상태를 다시 확인 |
| 필수 입력 누락 또는 잘못된 요청 | 400 | 등록 · 수정 화면에 입력 오류와 고칠 항목 안내 |
| 존재하지 않거나 권한 없는 사고 조회 | 404 | 다른 사용자의 정보 노출을 막으려고 같은 오류로 처리 |

```compare
401 Unauthorized | 403 Forbidden
뜻 | 인증 실패 — 누구인지 모름 | 인가 실패 — 누군지 알지만 권한 없음
이 프로젝트 | 이메일 / 비밀번호 불일치 | 승인 대기(PENDING) 기업 계정 로그인
풀려면 | 다시 로그인 | 권한을 얻어야 함 (관리자 승인)
```

> [!tip] 면접 팁
> 상태 코드는 "클라이언트가 다음에 무엇을 하면 되는지"를 알려 주는 신호다. 400은 입력을 고치고, 401은 다시 로그인하고, 409는 현재 상태를 다시 조회하라는 뜻으로 설명하면 깔끔하다.
