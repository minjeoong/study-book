qa:
  - q: 정규화는 왜 하나요? 1NF·2NF·3NF를 설명해 주세요.
    a: "데이터 중복을 줄여 삽입·삭제·갱신 이상을 막고 무결성을 지키기 위해서입니다. 1NF는 모든 컬럼이 원자값이어야 하고, 2NF는 복합키의 일부에만 종속된 컬럼을 분리하며, 3NF는 학번→학과코드→학과명처럼 키가 아닌 컬럼을 거쳐 결정되는 이행 종속을 분리합니다. 실무에서는 보통 3NF나 BCNF까지 적용합니다."
  - q: 3NF와 BCNF의 차이는?
    a: "BCNF는 모든 결정자가 후보키여야 한다는 더 엄격한 조건입니다. (교수, 과목, 강의실) 테이블에서 교수가 항상 같은 강의실을 쓰면 교수→강의실 종속이 생기는데, 교수는 후보키가 아니므로 BCNF 위반이라 교수-강의실 테이블을 따로 분리합니다. 3NF는 종속성 보존을 우선해 이런 경우를 허용할 수 있습니다."
  - q: 반정규화는 언제 하나요?
    a: "정규화가 과하면 조회 때 JOIN이 많아져 느려지므로, 대시보드·리포트·ML 피처 테이블처럼 읽기 중심인 곳에서 중복 컬럼이나 집계 컬럼을 일부러 둡니다. 대신 원본과 동기화해야 하는 부담이 생기므로 먼저 인덱스로 해결해 보고, 안전한 대안으로 Materialized View를 검토합니다."

```flow
비정규화 :: 한 셀에 "DB, 네트워크, OS" 여러 값
1NF :: 모든 컬럼이 원자값, 반복 그룹은 행이나 별도 테이블로
2NF :: (학번, 과목코드) 키에서 학번에만 종속된 학생이름 분리
3NF :: 학번 → 학과코드 → 학과명 이행 종속 분리
BCNF :: 모든 결정자가 후보키 (교수 → 강의실 분리)
```

| 이상 현상 | 학생·학과가 한 테이블에 섞여 있으면 |
| --- | --- |
| 삽입 이상 | 학생이 없으면 새 학과를 넣을 수 없음 (불필요한 데이터까지 필요) |
| 삭제 이상 | 마지막 학생을 지우면 학과 정보까지 사라짐 |
| 갱신 이상 | 학과명이 여러 행에 중복 → 일부만 고치면 불일치 |

```compare
정규화 유지 (OLTP) | 반정규화 허용 (OLAP)
중심 작업 | INSERT · UPDATE | 집계 SELECT
우선순위 | 무결성, 이상 현상 방지 | JOIN 비용 감소
기법 | 3NF~BCNF, 성능은 인덱스로 | 중복·집계 컬럼, Materialized View
예 | 은행 계좌, 주문 처리, 회원 | 대시보드, 보고서, ML 피처 테이블
```

- 4NF: 서로 독립인 다중값 분리 (직원-자격증, 직원-외국어를 각각 테이블로)
- 5NF: 분해 후 JOIN으로 원본을 정확히 복원 (조인 종속) — 이론상 중요, 실무는 3NF까지가 일반적
- 정규화 결과는 FK로 다시 연결: `students.major_id → majors.id` (3NF로 학과명 분리)

> [!tip] 면접 팁
> "정규화는 쓰기 무결성, 반정규화는 읽기 성능"이라는 트레이드오프로 정리하고, 반정규화 전에 인덱스와 Materialized View를 먼저 검토한다고 덧붙이면 좋다.
